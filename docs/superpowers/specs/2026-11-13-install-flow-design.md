# 安装流程改造：从“排程等待”到“同步安装器”

日期：2026-11-13
状态：待评审

## 一、意图

安装接入应当像装一个正常软件：用户点一次，进程接管，装完给出确定结果；不存在“关掉再开，可能装上也可能没装上”。安装期间不允许做会干扰的操作。

## 二、现状与问题

| 现状 | 问题 |
|---|---|
| 插件激活后只要可装就自动排程 | 用户没有同意动作，退出后宿主文件就被改写 |
| 排程后只弹一次 toast | toast 消失后无任何常驻状态，用户无法判断到底装没装 |
| 排程无法取消 | 反悔也只能等它执行 |
| 失败时把 PowerShell 原始报错弹在 toast | 看不懂，也没有重试或恢复入口 |
| 每次激活把 `update.mode` 改成 `none` | 静默修改用户设置 |
| 需要“退出全部 Cursor 窗口”才动手 | 结果不确定，且用户不知道何时完成 |

## 三、目标

- 一次明确的用户动作，同步完成写入与校验。
- 失败必须可回滚、可解释、可重试；不留半装状态。
- 安装期间限制会干扰的操作。
- 只有一个不可避免的等待：重启 Cursor 使新代码生效；重启由用户点击触发。
- 重启后自动校验并给出“已就绪”，不靠用户猜。

## 四、非目标

- 不改为运行时注入（Cursor 3.30.8 无可用原生模型 API，代价等同重写）。
- 不接入扩展市场自动更新。
- 不改动模型目录、消息插入、effort 等既有功能。

## 五、反目标

- “装了一半、状态说不清”。
- 安装过程中用户还能点保存配置、切换服务、再次安装。
- 安装结果依赖退出时序。

## 六、关键事实（已实测）

Cursor 正在运行时，14 个目标文件全部可以以写模式打开：`out/main.js`、`out/cli.js`、两个 workbench bundle、sharedProcess、cliProcessMain、extensionHostWorkerMain、mcpProcessMain、extensionHostProcess、ptyHostMain、`product.json`、三个 SDK bundle。因此不需要等 Cursor 退出即可写入，重启只是为了让新代码被加载。

## 七、方案（已选定）

### 状态机

```
未接入 ──点击安装──> 安装中 ──成功──> 已安装·待重启 ──重启──> 已就绪
                        │                                        │
                        └──失败/被占用──> 安装失败（已回滚）      └──校验不符──> 需要检查
```

- `未接入`：原始状态，可安装。
- `安装中`：同步写入，带进度；禁止其他操作。
- `已安装·待重启`：文件已写入并校验，等用户点重启。
- `已就绪`：重启后 revision 与目标一致，全部文件哈希与清单匹配。
- `安装失败`：已回滚，展示失败文件与原因，提供重试/查看日志/恢复备份。
- `被占用`：某个文件无法写入，展示文件名；提供“退出 Cursor 后自动完成”或“取消”。

### 交互

1. 配置页顶部常驻“接入状态”卡片，替代现在的 toast。文案随状态变化，按钮随状态变化（安装/重启/重试/取消/恢复）。
2. 点击安装 → 确认弹窗：将修改 14 个文件、备份目录、恢复方式、勾选“我了解会修改 Cursor 安装文件”、可选勾选“同时关闭 Cursor 自动更新”（默认不勾选）。
3. 确认后立即执行：webview 显示阻塞遮罩，进度文案逐文件更新。
4. 成功 → 关闭遮罩，显示“已安装，重启后生效”+「重启 Cursor」按钮；状态栏同时出现常驻项，点击打开配置页。
5. 用户点「重启 Cursor」→ 调用重载/重启命令，由用户主动触发。
6. 重启后激活即校验：revision、清单、逐文件哈希；通过则显示“已就绪”。

### 安装期间的操作限制

- 单例：正在安装时重复点击直接返回，不启动第二个任务。
- 命令守卫：安装进行中，保存配置、停用、再次安装一律拒绝并提示“安装进行中”。
- 实例锁：沿用备份目录下的 `operation.lock`，避免与外部脚本并发。

### 写入与校验

- 写前把每个原始文件快照到备份目录，写清单（相对路径、前后哈希）。
- 逐文件原子写（临时文件 + rename），写完立即校验哈希。
- 全部完成后校验 `product.json` 的 checksums。
- 任一步失败：按已写列表逆序回滚，逐个校验回滚结果；回滚失败标记 `recovery-required` 并给出备份路径。

### 被占用的回退

- 不在后台静默排队。当场报出具体文件，并给两个选择：
  - 「退出 Cursor 后自动完成」：沿用现有 worker + `job.json` 机制，状态栏显示“等待退出”，可取消。
  - 「取消」：不留下任何排队任务。
- 取消排程：终止 worker 进程，`job.json` 置 `cancelled`，状态回到未接入。

### 设置写入

- `update.mode` 只在用户在确认弹窗勾选后写入，不再每次激活静默修改。
- 卸载/停用时不自动恢复，交由用户在设置里决定；README 说明。

## 八、影响面

- `patcher.cjs`：新增“立即应用”入口（不依赖 `--wait`），暴露逐文件进度回调与占用错误类型。
- `installation.cjs`：状态机重写；移除激活时自动排程与静默改设置；新增取消、重试、校验。
- `settings.cjs` / `media/config.*`：顶部状态卡片、阻塞遮罩、确认弹窗、勾选项。
- `extension.cjs`：状态栏项、重启命令、命令守卫。
- `README.md` / `CHANGELOG.md`：流程与恢复说明。

## 九、验证方式

- 离线：用真实 Cursor 3.30.8 备份做目标目录的副本，跑立即安装 → 校验清单与哈希 → 模拟中途失败验证回滚 → 模拟文件占用验证分支。全程不触碰真实安装目录。
- 状态机：单测覆盖未接入/安装中/待重启/就绪/失败/被占用/等待退出/取消。
- 配置页：无头浏览器夹具覆盖遮罩、按钮禁用、确认勾选、状态文案。
- 真实环境：安装后由用户点重启，重启后读状态确认“已就绪”。

## 十、留给实现者的决定

- 进度展示用 VS Code 通知进度还是 webview 内进度条：优先 webview，因为配置页本来就是主入口；命令面板触发时用通知进度兜底。
- 「重启 Cursor」调用 `workbench.action.reloadWindow` 还是完整重启：先用 reloadWindow，若验证发现原生补丁未生效则改为提示用户完整退出。
- 备份保留策略：沿用现有按时间戳目录，默认不自动清理。
