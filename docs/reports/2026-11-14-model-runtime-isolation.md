# 0.10.0 模型执行隔离

目标环境：Cursor 3.30.8，Windows x64。适配器修订 42。

## 问题与改动

旧接入通过全局关闭 AgentHost 来选择兼容执行路径，会同时改变官方模型的执行方式。另一个问题是原生子代理在创建和真正运行时分别整理模型配置，只修复创建入口仍会在运行入口丢失服务或推理强度。

现在使用配置目录中的完整模型身份选择第三方路径。官方模型的 AgentHost 开关、权限判断、原始执行实现和默认 SDK 保留。服务商原始模型名仅在第三方请求边界转换，同名模型不会串用地址、密钥或参数。保存目录只通知列表更新，不运行官方配置的全局迁移。

第三方推理由 Cursor 自带的独立本地运行时执行。工具使用单独的提供者注册槽；这个工具提供者复用 AgentHost 已初始化的原生资源工厂，支持 shared-runtime 和 agent-host-exec 两种实现，不构造第二套文件、终端或审批系统。AgentHost 扩展仅新增一个工具提供者工厂和一次注册，删除这两处新增代码后与原文件完全一致。

工具会话使用独立身份，传递原生请求元数据，复用原生工具消息序列化及取消。后台终端继续使用 composer 原有的保活机制，资源按创建时的通道归属清理，切换模型不会改变旧资源的归属。

子代理在创建和运行两个原生入口统一解析模型，空参数继承父对话的选择；恢复已有第三方子代理时保留其原服务。官方模型不按第三方的原始模型别名重新映射。

## 验证

- 从完整原始备份生成补丁，13 个 JavaScript bundle 均通过语法解析；默认 exec SDK 与原件逐字节相同，官方 host 的既有实现未改写。
- 执行原生模型配置整理、setter、子代理创建、fork、恢复和完整运行入口，验证两个服务的同名模型、low/high/max 和官方目录未加载的场景。
- 执行原生请求分发，验证新鲜凭据按服务获取、请求对象不被污染、官方发送不读取第三方密钥。
- 执行实际原生 controlled-exec manager 与 protobuf 编解码，验证工具响应及结束帧；执行两个原生资源工厂入口。
- 执行 IDE 与 Agent 窗口的原生工具注册、会话初始化及清理方法，验证独立注册和后台任务保活。
- 执行消息插入的原生序列化与双向 RPC 回调，验证顺序、去重、送达确认、失败重新入队、运行结束和取消。
- 使用实际配置页脚本进行无界面浏览器检查，验证 Key 显示、隐藏、输入及切换服务时的异步回复归属。

主要命令：

```text
node --experimental-vm-modules validation/native-isolation-0.10.0.cjs
node validation/tool-isolation-0.10.0.cjs
node validation/insertion-0.9.0.cjs --dedicated
```

验证使用真实原生方法和序列化代码，外部应用服务及工具资源采用离线夹具。没有调用用户的收费模型接口，没有测量实际服务商首字延迟，也没有在运行中的 Cursor 安装或重启这版。离线结果不能代替安装后的端到端验证。

0.9.13 的子代理报告属于历史记录，其快照/BOM 结论不代表本次问题的完整原因。
